# 2026-09-12

## 講座運営アプリ 段階 1（アカウント準備）

Hono / Cloudflare 習得用の個人開発プロジェクトについて、設計書 7 章の段階 1 を実施した。

LINE 側は、プロバイダー kouza-app-provider を作成し、公式アカウント kouza-app-channel（未認証・コミュニケーションプラン）を開設、Official Account Manager から Messaging API を有効化した。チャネルシークレットとアクセストークンは発行済みで、リポジトリ外に保管している。Cloudflare アカウントも作成済み。

作業を通じて設計書の想定と実態のずれが 2 点見つかり、あわせて未定義だった仕様を 1 点決めた。PR #1 として設計書に反映した。

### 設計書の想定と実態のずれ

Messaging API チャネルは LINE Developers Console から直接作成できなくなっていた。公式アカウントを先に開設し、Official Account Manager 側で Messaging API を有効化するとチャネルが生成される、という逆順に変わっている。チャネルはプロバイダー間を移動できないため、有効化時のプロバイダー選択を誤ると作り直しになる。この注意点も設計書に残した。

Webhook は段階 1 では設定できないことが判明した。Official Account Manager の Webhook トグルは Webhook URL を登録するまで操作できず、その URL は Workers のデプロイまで確定しない。完了条件を段階 2 へ移した。

### 画像以外のメッセージの扱いを決めた

設計書は画像の受信しか定義していなかったが、message イベントはテキストやスタンプでも飛んでくる。無視すると受講生から見て無反応になるため、type で分岐し画像以外には定型文を応答メッセージで返す方針とした。応答メッセージは課金対象外なので無料枠を消費しない。

無視する案と、LINE 標準の応答メッセージ機能に任せる案も検討した。後者はコード不要だが、F1 の自作応答と二重に届き検証時の切り分けが困難になるため採らなかった。

### 受信内容の確認先を整理した

Official Account Manager のチャットはオフのまま運用する。オンにすると受信イベントをチャットが握り、Webhook との切り分けが難しくなるため。受信内容は wrangler tail、R2、D1、自分の LINE トーク画面で確認する方針を設計書に明記した。

### 申し送り

公式アカウント開設時、連携した LINE アカウントへ自動で友だち追加され、友だち数が 1 になっている。設計書 F1 が想定していた「開発開始時点で自分は友だち追加済み」という状態が現実になったため、段階 5 では follow イベントが飛んでこない。students の最初の 1 行は手動 INSERT かブロック解除で作る必要がある。

段階 2 に入る前に wrangler のログインが必要。デプロイは外部公開にあたるため実行前に確認する。
