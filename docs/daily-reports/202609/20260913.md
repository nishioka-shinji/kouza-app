# 2026-09-13

## 講座運営アプリ 段階 2（Hono + Workers の疎通）

設計書 7 章の段階 2 を完了した。ローカルとデプロイ先の両方で Hello World が返り、Webhook URL の登録と有効化まで通した。PR #4 と #5 としてマージ済み。

Node がこの環境に入っていなかったため、mise で 24.21.0 を固定するところから始めた。他のツールを mise で管理している環境に合わせている。依存は Hono 本体と wrangler / typescript のみに絞り、設計方針の「ライブラリを増やさない」に沿わせた。

### nodejs_compat を有効にしない

`wrangler types` が `@types/node` の導入を促してくるが、フラグごと外した。有効にすると Workers で動かない Node API を書けてしまい、「`@line/bot-sdk` 本体は Node 依存なので使わない」という既存の方針と衝突する。生成された型定義に `node:` の参照がないことは確認した。

### 公開 URL を独自ドメインに固定した

当初 `workers.dev` にデプロイしたが、Webhook URL として登録する前に `kouza-app.muso-lab.dev` へ移した。一度 LINE に登録すると変更しにくく、`workers.dev` は Worker 名に URL が引きずられるため。既存の `care.muso-lab.dev` などとも揃う。

`routes` を明示した副作用で `workers.dev` のルートは無効になった。`workers_dev = true` で併存もできるが、そのままにした。段階 5 で署名検証を入れるとき、Webhook の入口が複数あると考えることが増えるため。

### デプロイ方式は手元からに寄せる

これまで UI の GitHub 連携（Workers Builds）で運用していたが、このプロジェクトは手元から `wrangler deploy` で進める。段階 5・6 は LINE の実機確認を挟むので、push とビルドを待たずに反映できるほうが切り分けのループが速い。運用が固まったら切り替えを検討する。

### Webhook の登録は Developers Console 側

Official Account Manager には Webhook トグルがあるが URL の入力欄がなく、登録は LINE Developers Console の Messaging API 設定タブでしかできない。段階 1 で「トグルを操作できない」としていた件は、URL 登録の場所が別だったことによる。

設定画面のトグルだけでは届いている保証にならないので、`wrangler tail` を流した状態で LINE からメッセージを送り、`POST https://kouza-app.muso-lab.dev/webhook - Ok` が記録されることを確認した。`/webhook` は段階 5 まで未実装で 404 を返すが、経路が通っていることは確かめられた。

### 申し送り

作業中に `/goal` の Stop hook が無限ループに陥った。完了条件に「デプロイ先で Hello World が返る」を含めていたが、デプロイは OAuth 認証と権限分類器の承認を要し、こちらからは実行できない。hook は「未達だから続けろ」と再起動し続け、こちらは「実行できない」と返すだけの往復が続いた。実行主体が自分にない条件を hook の完了条件に置かない、という教訓になる。

Official Account Manager の応答設定に「応答モード」という項目は現行 UI に存在しない。「チャット」トグルがその役割を兼ねており、オフなら Bot モード相当になる。

段階 4 の LIFF 設定でも同じくエンドポイント URL の登録が要る。`kouza-app.muso-lab.dev` のサブパスを充てることになる。
